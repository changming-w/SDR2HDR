## 摘要

本报告分两部分：

- **第一部分**用两组实验，量化“显示端白平衡/gamma 校正 LUT”和“luma-only 模型”的先后顺序对最终颜色的影响；
- **第二部分**（文末第 11–17 节）只讨论 LUT 作为模型输入变换对模型输出的影响，不涉及白点对错。

两条路径：

```text
Path A：SDR → 模型（×k）→ 校正 LUT → 面板
Path B：SDR → 校正 LUT → 模型（×k）→ 面板
```

其中 `k` 是模型对同一像素 RGB 三通道施加的共同码值增益：

```text
out = k · RGB
```

核心结论：

1. **Path A 是正确顺序。** 模型在码值域乘 `k`，经过目标 gamma 2.2 后，最终线性光统一乘 `k^2.2`，三通道比例不变，白点保持。
2. **Path B 会改变颜色。** 校正 LUT 先按原始码值 `V` 配平三通道，模型再把 LUT 输出码统一乘 `k`。码值比例虽然保持不变，但面板三通道 gamma 不同，最终线性光变成逐通道的 `k^{γ_c}`，白点偏移。
3. **关键不等式：**

   ```text
   C(kV) ≠ k · C(V)
   ```

   LUT 是非线性逆函数。正确的新工作点码值是 `C(kV)`，不是把旧码值 `C(V)` 直接乘 `k`。
4. **第二部分只讨论模型输入域影响。** 把 LUT 看成输入变换 `G`，比较 `M(x)` 与 `M(G(x))`。5 帧抽查中多数帧模型增益近似稳定，但暗场高增益帧会出现明显增益压缩，详见第 11–17 节。

第一部分两组实验的主要数据：

| 实验 | 数据 | 关键结果 |
|---|---|---|
| 灰阶扫描 | 7 个灰阶 × 4 个增益 = 28 组 | Path A 白点误差最大 `Δu'v'=0.00151`；Path B 最大 `0.01303`；`ΔE(A,B)` 最大 `6.510` |
| 真实图像 | 26 张 4K 帧，4× 降采样 | Path B 相对 Path A 的 `ΔE` 均值 `0.378–2.560`；最差帧 `69.00%` 像素 `ΔE>2`；22/26 帧灰色像素白点误差均值 `>0.004` |

> **第二部分（文末第 11–17 节）**只讨论模型输入/输出，不计算白点或 ΔE。5 帧抽查显示：多数帧模型增益近似稳定，但暗场高增益帧会出现明显增益压缩。

## 0. 术语与范围

### 0.1 三条 1D LUT，不是 3D LUT

脚本实际构造的是 **三条逐通道 1D LUT**：

```text
C_R(V), C_G(V), C_B(V)
```

每条 LUT 的输入是同一个目标码值 `V`，输出是该通道自己的面板驱动码。

它们不是 3 个 3D LUT。3D LUT 会同时处理 RGB 三通道之间的耦合；本脚本假设：

- 三个通道相互独立；
- 原色为 BT.709；
- 只需要逐通道 EOTF 和白平衡校正。

因此，本文的结论严格适用于“3 条 1D LUT + 逐通道面板”的模型。如果现场管线真的使用 3D LUT，需要重新做 3D LUT 的端到端实验。

### 0.2 Path A 与 Path B

| 名称 | 信号流 | 说明 |
|---|---|---|
| Path A | `V → ×k → C_c(·) → 面板` | 模型在前，LUT 在后；本报告推荐顺序 |
| Path B | `V → C_c(·) → ×k → 面板` | LUT 在前，模型在后；本报告称为“当前做法”或“错误顺序” |

### 0.3 本报告回答什么

本报告回答：

- 在给定的合成面板模型下，顺序本身会造成多大颜色误差；
- 这个误差在白点、灰阶、真实图像上分别是什么量级；
- 误差的数学来源是什么；
- 为什么“LUT 后码值比例不变”不能保证“面板发光比例不变”。

本报告暂不回答：

- 真实把 LUT 移到模型前面后，模型重新推理的端到端误差；
- 特定真实显示器的精确误差；
- 3D LUT、通道串扰、局部调光等复杂管线的影响。

这些在“局限性”中说明。

## 1. 实验目的

### 1.1 问题

luma-only 模型对像素的作用可以写成：

```text
out_R = k · in_R
out_G = k · in_G
out_B = k · in_B
```

它对三个通道乘同一个 `k`。

直觉上，“三个通道同乘一个系数，颜色不变”。但这个直觉的准确前提是：

> 乘的是**线性光 RGB**，或者三个通道经过的是**同一条纯 gamma 曲线**。

显示端校正 LUT 工作在**面板驱动码**域，而且面板三通道的原生 gamma、S 曲线、满幅都不同。因此需要实验回答：

1. 把 LUT 放在模型前或后，最终线性光是否相同？
2. 如果不同，是亮度不同还是颜色不同？
3. 在灰阶和真实图像上，误差有多大？

### 1.2 两个实验

| 实验 | 目的 | 数据规模 |
|---|---|---|
| 实验一：灰阶扫描 | 在受控条件下隔离顺序效应，检查白点和 ΔE | 7 个 `V` × 4 个 `k` = 28 组 |
| 实验二：真实图像 | 用真实模型输入/输出估计逐像素 `k`，统计真实画面的颜色误差 | 26 张 4K 帧，4× 降采样 |

## 2. 面板假设与三条校正 LUT

### 2.1 虚拟面板参数

脚本假设的虚拟面板参数如下：

| 参数 | 代码 | 值 | 含义 |
|---|---|---|---|
| 原生 gamma | `NATIVE_GAMMA` | R 2.45，G 2.25，B 2.05 | 三通道原生幂指数，故意各不相同 |
| S 曲线强度 | `S_CURVE` | R 0.10，G 0.05，B 0.15 | 在纯 gamma 上叠加的中间调弯曲 |
| 通道满幅 | `AMP` | R 0.90，G 1.00，B 1.10 | 三通道满幅线性亮度 |
| 目标 gamma | `TARGET_GAMMA` | 2.2 | 校正后的目标 EOTF |
| LUT 输入点数 | `LUT_SIZE` | 1024 | 10bit 输入采样 |
| LUT 输出位宽 | `LUT_OUT_BITS` | 10 | 输出量化到 10bit |
| 公共目标白电平 | `s` | 0.90 | `min(AMP)` |

原生白点偏蓝：码值全 1 时，三通道线性光为：

```text
(0.90, 1.00, 1.10)
```

R 最弱、B 最强。

### 2.2 面板原生响应

面板响应定义为：

\[
P_c(v)=\text{clip}\left(v^{\gamma_c}+S_c\sin(\pi v)v^{\gamma_c}(1-v)2,\ 0,1\right)
\]

其中：

- `v` 是面板驱动码，范围 `[0,1]`；
- `P_c(v)` 是归一化线性亮度，范围 `[0,1]`；
- `γ_c` 是原生 gamma；
- `S_c` 是 S 曲线强度；
- `clip` 保证响应不超出 `[0,1]`。

S 曲线项的作用：

- 在 `v=0` 和 `v=1` 处为 0；
- 主要影响中间调；
- `S_c=0` 时退化为纯 gamma。

在 `v=0.5` 时：

\[
\sin(\pi/2)=1,\qquad (1-0.5)\times2=1
\]

所以：

\[
P_c(0.5)=(1+S_c)\cdot0.5^{\gamma_c}
\]

也就是说，在中间灰附近：

```text
R 比纯 gamma 高约 10%
G 比纯 gamma 高约 5%
B 比纯 gamma 高约 15%
```

三通道的 S 强度不同，使面板响应不只是“三个不同指数的幂函数”，而是逐通道、随电平变化的非线性曲线。

### 2.3 三条校正 LUT 的构造

目标是让输入码值 `V` 经过 LUT 和面板后，三个通道都发出相同的目标线性光：

\[
a_c P_c(C_c(V))=sV^{2.2}
\]

其中：

- `C_c(V)`：通道 `c` 的 LUT 输出驱动码；
- `a_c`：通道 `c` 的满幅线性亮度；
- `s`：公共目标白电平。

对 `P_c` 求逆：

\[
C_c(V)=P_c^{-1}\left(\frac{sV^{2.2}}{a_c}\right)
\]

这就是三条 1D LUT 的定义式。

为什么 `s=min(AMP)=0.90`：

- R 通道满幅只有 0.90；
- 如果目标白电平设为 1.0，R 永远达不到；
- 取 `0.9` 让三个通道都能达到公共白点；
- G/B 分别留出 0.10 和 0.20 的 headroom。

LUT 的数值实现：

```python
dense = np.linspace(0, 1, 65536)
resp = panel_native(dense, ch)
resp = np.maximum.accumulate(resp)

target = s * np.power(vin, TARGET_GAMMA) / AMP[i]
code = np.interp(target, resp, dense)

q = 2 ** LUT_OUT_BITS - 1
luts.append(np.round(code * q) / q)
```

步骤：

1. 在 `[0,1]` 上取 65536 个候选驱动码；
2. 计算每个驱动码的面板响应；
3. 用 `np.maximum.accumulate` 强制响应单调，保证可求逆；
4. 计算目标响应 `sV^2.2/a_c`；
5. 用 `np.interp` 反查驱动码；
6. 量化到 10bit；
7. 运行时在 1024 个 LUT 点之间线性插值。

三个灰阶的 LUT 示例：

| 输入 `V` | `C_R(V)` | `C_G(V)` | `C_B(V)` |
|---:|---:|---:|---:|
| 0.2 | 0.2264 | 0.1941 | 0.1531 |
| 0.5 | 0.5166 | 0.4736 | 0.3993 |
| 0.8 | 0.8117 | 0.7619 | 0.6880 |

可以看到：

```text
C_R > C_G > C_B
```

R 最弱，所以驱动码最大；B 最强，所以驱动码最小。这正是 LUT 在做白平衡预补偿。

无模型时，校正后灰阶的白点误差为：

```text
max Δu'v' = 0.00107
```

已经低于常用的 0.004 可见阈值，说明 LUT 本身是有效的。这个 0.00107 是 10bit 量化和数值反演的噪声底。

## 3. 两条路径与全流程公式

### 3.1 符号

| 符号 | 含义 |
|---|---|
| `V` | 输入目标显示码值，范围 `[0,1]` |
| `k` | luma-only 模型的逐像素标量增益，作用在码值域 |
| `P_c` | 面板通道 `c` 的原生响应 |
| `a_c` | 面板通道 `c` 的满幅线性亮度 |
| `C_c` | 通道 `c` 的校正 1D LUT |
| `s` | 公共目标白电平，`s=min(a_c)=0.9` |
| `code_c` | 最终送给面板通道 `c` 的驱动码 |
| `L_c` | 脚本归一化后的线性光 |

脚本的线性光定义为：

\[
L_c=\frac{a_cP_c(\text{code}_c)}{s}
\]

物理线性光是：

\[
L_c^{\text{phys}}=a_cP_c(\text{code}_c)
\]

除以 `s` 只是把公共白电平归一化到 1，不改变三通道比例，也不影响 ΔE/Δu'v'。

### 3.2 LUT 的基本性质

由 LUT 构造式可知，忽略量化误差：

\[
a_cP_c(C_c(V))=sV^{2.2}
\]

这就是后面所有推导的出发点。

它的含义是：

> 在输入码值 `V` 处，LUT 输出的三个驱动码 `C_R(V), C_G(V), C_B(V)`，经过三条不同的面板曲线后，刚好发出相同的线性光 `sV^2.2`。

### 3.3 Path A：模型在前，LUT 在后

信号流：

```text
V → ×k → kV → C_c(·) → 面板
```

面板驱动码：

\[
\text{code}_c^A=C_c(kV)
\]

最终线性光：

\[
L_c^A=\frac{a_cP_c(C_c(kV))}{s}
\]

代入 LUT 性质：

\[
L_c^A=\frac{s(kV)^{2.2}}{s}=(kV)^{2.2}=k^{2.2}V^{2.2}
\]

三通道都是同一个 `k^{2.2}`，所以：

- 亮度统一变化；
- RGB 比例不变；
- 白点保持；
- 颜色不变。

未 clipping 时成立。若 `kV>1`，LUT 输入被 clip：

\[
L_c^A=\min(kV,1)^{2.2}
\]

三通道同时 clip，仍然保持中性。

### 3.4 Path B：LUT 在前，模型在后

信号流：

```text
V → C_c(·) → C_c(V) → ×k → 面板
```

面板驱动码：

\[
\text{code}_c^B=kC_c(V)
\]

最终线性光：

\[
L_c^B=\frac{a_cP_c(kC_c(V))}{s}
\]

如果面板是纯 gamma：

\[
P_c(x)=x^{\gamma_c}
\]

则：

\[
L_c^B
=\frac{a_c\left(kC_c(V)\right)^{\gamma_c}}{s}
=k^{\gamma_c}\frac{a_cC_c(V)^{\gamma_c}}{s}
=k^{\gamma_c}V^{2.2}
\]

注意这里是：

```text
R：k^2.45
G：k^2.25
B：k^2.05
```

不是统一的 `k^2.2`。

### 3.5 两条路径的比值

\[
\frac{L_c^B}{L_c^A}
=\frac{k^{\gamma_c}V^{2.2}}{k^{2.2}V^{2.2}}
=k^{\gamma_c-2.2}
\]

脚本参数：

```text
γ_R = 2.45  →  γ_R - 2.2 = +0.25
γ_G = 2.25  →  γ_G - 2.2 = +0.05
γ_B = 2.05  →  γ_B - 2.2 = -0.15
```

所以三通道比值不同，白点偏移。

特殊情况：

1. `γ_R=γ_G=γ_B=2.2`：比值为 1，两种顺序完全等价；
2. 三通道 gamma 相同但不等于 2.2：比值三通道相同，颜色不变，但亮度增益从 `k^2.2` 变成 `k^γ`；
3. 三通道 gamma 不同：逐通道比值不同，产生色偏。

### 3.6 clipping 阈值不同

Path A 的 clipping 条件：

\[
kV=1
\]

阈值：

\[
k_A=\frac{1}{V}
\]

三通道相同。

Path B 的 clipping 条件：

\[
kC_c(V)=1
\]

阈值：

\[
k_c=\frac{1}{C_c(V)}
\]

三通道不同。

因为：

```text
C_R > C_G > C_B
```

所以：

```text
k_R < k_G < k_B
```

R 最先 clip，B 最后 clip。

以 `V=0.9` 为例：

```text
C(0.9) = [0.9078, 0.8589, 0.7954]
1/C    = [1.102,  1.164,  1.257]
1/V    = 1.111
```

当 `k=1.2` 时：

- Path A：`k > 1/V`，三通道一起 clip，输出仍然中性；
- Path B：R、G 已经 clip，B 还没 clip，B 相对更亮，高光偏冷。

这是 Path B 的第二个独立误差源：不仅有 `k^{γ_c}` 的 gamma 失配，还有 clipping 顺序不同。

### 3.7 S 曲线的影响

真实面板响应含 S 曲线时，`P_c` 不是纯幂律：

\[
P_c(kx)\neq k^{\gamma_c}P_c(x)
\]

所以 `k^{γ_c}` 只是一阶解释。脚本的数值实验使用完整的 `P_c`，包含：

- S 曲线；
- 10bit LUT 量化；
- 单调化；
- Path A/B 不同位置的 clip；
- 三通道满幅差异。

因此：

- 数学推导解释机制；
- 数值实验给出实际量级。

## 4. 指标与 `k` 估计

### 4.1 模型增益 `k`

脚本读取真实模型的输入 `i` 和输出 `o`，逐像素估计：

\[
k=\frac{\sum_c o_c}{\sum_c i_c}
\]

对 luma-only 模型，未 clipping 时：

\[
o\approx k\cdot i
\]

所以三通道求和比就是增益。极暗像素用 `k=1` 兜底，避免除零。

> 注意：真实图像中的 `k` 来自 8bit PNG 的输入/输出比值，包含量化、舍入和 clipping，是真实模型增益的合理代理，不是内部浮点增益的精确值。

### 4.2 颜色指标

线性 RGB 转 XYZ：

\[
XYZ=M_{709}\cdot L
\]

u'v'：

\[
u'=\frac{4X}{X+15Y+3Z},\qquad
v'=\frac{9Y}{X+15Y+3Z}
\]

Δu'v'：

\[
\Delta u'v'=\sqrt{(u'_A-u'_B)^2+(v'_A-v'_B)^2}
\]

Lab 和 ΔE76：

\[
\Delta E_{76}=\|Lab_A-Lab_B\|_2
\]

| 指标 | 含义 | 常用阈值 |
|---|---|---|
| Δu'v' | 只反映色度/白点偏移，不含明度 | 约 0.004 可见 |
| ΔE76 | 同时包含明度和色度 | 约 2 明显可见 |
| 亮度增益 | 输出 Y / 参考 Y | 衡量亮度，不含色度 |

### 4.3 统计口径

- 灰阶：每个 `(V,k)` 输出一个 Δu'v' 和一个 ΔE；
- 图像：每个像素一个 `k`、一个 ΔE；
- 帧级统计：ΔE 均值、p99、最大值、ΔE>2 占比；
- 灰色像素白点：只统计 `ptp(i)<2/255` 且 `sum(i)>0.15` 的像素；
- 热力图：`clip(ΔE/5×255,0,255)`，只用于看空间分布。

## 5. 全流程算例

这一节用具体像素把两条路径从输入码一步步算到最终线性光。

### 5.1 算例一：灰阶像素

取：

```text
V = (0.5, 0.5, 0.5)
k = 0.8
```

#### 基准：不加模型

LUT 输出：

```text
C(V) = [0.516618, 0.473607, 0.399316]
```

线性光：

```text
L0 = [0.217416, 0.217597, 0.218024]
```

比例：

```text
0.9988 : 0.9996 : 1.0016 ≈ 1 : 1 : 1
```

#### Path A

码值先乘 `k`：

```text
kV = [0.4, 0.4, 0.4]
```

重新查 LUT：

```text
C(kV) = [0.420528, 0.380254, 0.313978]
```

线性光：

```text
L_A = [0.133205, 0.133433, 0.133227]
```

比例：

```text
0.9994 : 1.0011 : 0.9995 ≈ 1 : 1 : 1
```

相对基准的增益：

```text
[0.6127, 0.6132, 0.6111] ≈ k^2.2 = 0.6121
```

三通道统一，颜色不变。

#### Path B

先查 LUT：

```text
C(V) = [0.516618, 0.473607, 0.399316]
```

码值比例：

```text
1.1154 : 1.0225 : 0.8621
```

乘 `k=0.8`：

```text
kC(V) = [0.413294, 0.378886, 0.319453]
```

码值比例仍然是：

```text
1.1154 : 1.0225 : 0.8621
```

**码值比例完全没变。**

## 6. 实验一：灰阶扫描

### 6.1 设置


每个组合：

- 计算 Path A/B 相对 D65 的 Δu'v'；

### 6.3 结果分析

#### 第一，Path A 的白点误差始终在量化噪声底附近

- Path A 的 `Δu'v'` 范围：`0.00004–0.00151`；
- 全部低于 0.004 可见阈值；
- 说明“模型在前、LUT 在后”确实能保持 D65。

#### 第二，Path B 的白点误差明显超标

- Path B 的 `Δu'v'` 范围：`0.00234–0.01303`；
- 最大值 `0.01303` 是 0.004 阈值的 3 倍多；
- `k=0.6` 时，7 个灰阶全部 `>0.004`；
- `k=0.8` 时，多数灰阶 `>0.004`；
- `k=1.2` 时，高亮灰阶因 clipping 出现更大的误差。

#### 第三，亮度接近不代表颜色正确

`V=0.9, k=0.6`：

```text
增益 A = 0.325
增益 B = 0.330
ΔE(A,B) = 6.510
```

亮度几乎一样，但颜色差很大。原因是：

- Y 由 G 主导（权重 0.7152）；
- G 的 gamma 2.25 离 2.2 很近；
- 亮度加权后平均增益接近 `k^2.2`；
- 但 R/B 的比例已经变了，所以白点/色度错了。

所以不能用“亮度差不多”判断顺序正确，必须看色度/ΔE。

#### 第四，Path A 的增益与理论一致

例如：

- `V=0.5, k=0.6`：A=0.326，理论 0.325；
- `V=0.9, k=1.2`：A=1.260，理论 1.261（含 clipping）。

Path B 则明显偏离：

- `V=0.9, k=1.2`：B=1.370，A=1.260；
- 这不是“颜色差一点”，而是 B 利用了 G/B 的 headroom，亮度也超了，同时颜色还偏了。

#### 第五，色偏方向随 `k` 和 clipping 变化

用 B 输出 u'v' 减 D65：

| 条件 | B−D65 (Δu', Δv') | 表现 |
|---|---|---|
| V=0.5, k=0.8 | (-0.0019, -0.0032) | 偏蓝 |
| V=0.5, k=1.2 | (+0.0012, +0.0027) | 偏暖 |
| V=0.9, k=1.2 | (-0.0049, -0.0012) | 高光 clipping 导致偏冷，方向反转 |

所以不能简单说“`k<1` 一定偏蓝、`k>1` 一定偏红”：

- 未 clipping 的中低亮度区，方向符合幂律；
- 高光区，clipping 顺序会改变方向；
- 但无论方向如何，误差都很大。

## 8. 结论与工程建议

### 8.1 正确顺序

```text
SDR → 模型（×k）→ 白平衡/校正 LUT → 面板
```

白平衡/校正 LUT 放在模型**后面**。

原因：

1. luma-only 模型在码值域只改变亮度，`out=k·RGB`，色度天然不变；
2. 校正 LUT 是面板响应的逆，必须作为最后一步，把目标码值翻译成具体面板的驱动码；
3. 这样最终线性光为 `sV^2.2k^2.2`，三通道一致，白点保持 D65。

### 8.2 如果当前是 Path B，怎么修

优先级从高到低：

1. **把 LUT 移到模型后面**（推荐）。这是最干净、最符合物理意义的做法。
2. 如果 LUT 必须在前，按通道补偿增益。纯 gamma 下需要：

   \[
   k_c=k^{2.2/\gamma_c}
   \]

   但这只在纯幂律、无 clipping 时近似成立；有 S 曲线和 clipping 时，需要数值求解：

   \[
   P_c(k_cC_c(V))=P_c(C_c(kV))
   \]

   解随 `V` 变化，不推荐。
3. 在 panel code 解码到线性光后做增益，再重新编码。等价于把增益放到正确的线性域。
4. 如果模型训练时输入本来就是 LUT 后的 panel code，那属于另一套 pipeline，需要重新训练/标定，不能只交换顺序。

### 8.3 验收标准

建议：

- 灰阶白点误差 `Δu'v' < 0.004`；
- 大部分像素 `ΔE < 2`；
- 高光区没有明显冷暖翻转；
- 灰色像素白点误差在全亮度范围内稳定。

当前 Path B：

- 灰阶最大 `Δu'v'=0.01303`，最大 `ΔE=6.510`；
- 26 帧中 22 帧灰色白点误差均值 >0.004；
- 最差帧 69.00% 像素 `ΔE>2`。

已经明显不满足。

## 9. 局限性与后续实验

### 9.1 局限性

1. **面板参数是合成假设**，不是实测的某台显示器。脚本证明的是机制和量级，不是特定设备的精确误差。真实面板需要实测 `P_c` 和 `a_c` 后重新跑。
2. **A/B 使用同一个 `k`**。真实把 LUT 移到模型前面后，模型输入分布会从 SDR 码值变成 panel code，`k` 本身也会变，误差可能更大或不同。脚本隔离的是“顺序”这一个变量，不是完整的端到端重跑。
3. **`k` 从 8bit 图像估计**，包含量化、clipping 和舍入；极暗像素用 `k=1` 兜底。
4. **4× 降采样**加速，统计上可接受，但不是逐像素全分辨率。
5. **0.004 和 ΔE>2 是经验阈值**，不是严格标准；不同观察条件、不同面板会有所不同。
6. **Path A/B 的 clipping 行为不同**：Path A 在 LUT 前 clip，Path B 在 LUT 后逐通道 clip。高光区的亮度增益对比会受 headroom 影响；颜色结论是稳健的，但亮度数字要结合 clipping 解释。
7. **S 曲线让有效指数随 `V` 变化**，纯幂律推导只是一阶解释；真正的证据是脚本的数值结果。
8. **真实显示管线可能还有 3D LUT、矩阵、局部调光、tone mapping 等**；脚本只建模了 3×1D LUT + 逐通道 EOTF。
9. **脚本不评价模型本身的画质**。它比较的是“同一模型增益下，两种顺序造成的显示差异”，不是模型输出与 HDR 参考的差距。
10. **没有测试 3D LUT**。如果现场使用 3D LUT，需要重新做 3D LUT 的端到端实验。

### 9.2 后续实验：A / B_fixed / B_actual

当前实验只隔离了“顺序”本身。要证明“真实部署成 Path B 后的总影响”，建议补一个端到端实验：

```text
A        : x → M → y → G → 面板
B_fixed  : x → G → ×k_A → 面板
B_actual : x → G → M → y' → 面板
```

其中：

```text
k_A = sum(M(x)) / sum(x)
```

- **A**：模型在前、LUT 在后，正确顺序；
- **B_fixed**：当前脚本的 Path B，用 A 的同一个 `k_A`，只改变顺序；
- **B_actual**：真实“LUT 在前、模型在后”，模型输入变成 LUT 编码后的图像，`k` 重新计算。

三组差值说明：

| 对比 | 说明 |
|---|---|
| `A vs B_fixed` | 纯顺序效应 |
| `B_fixed vs B_actual` | 模型输入域变化效应 |
| `A vs B_actual` | 真实部署成 B 时的总影响 |

如果 `A vs B_fixed` 很大，说明顺序本身有问题；  
如果 `B_fixed vs B_actual` 也很大，说明模型对输入域变化敏感；  
如果 `A vs B_actual ≈ A vs B_fixed`，说明固定 `k` 实验已经足够代表实际影响。

实现时需要确认：

1. 你的白平衡模块具体是什么：线性矩阵、3×1D LUT，还是含 gamma 的 3×1D LUT？
2. 模型输出在哪个信号域：SDR BT.709、HDR PQ/HLG，还是别的？
3. 面板是 SDR 还是 HDR，是否有实测 EOTF/白点？
4. 是否允许微调/重训？

> 第二部分的第 11–17 节已经把 `B_actual` 的面板去掉，只比较模型输出，做了 5 帧 `B_model` 抽查，专门测量模型输入域变化对 `k` 的影响；显示域的 `A vs B_actual` 总影响仍未做全量。

# 第二部分：LUT 作为模型输入变换的影响

> 本部分只讨论模型输入/输出，不讨论白点、ΔE、Δu'v'。  
> 第一部分回答“顺序本身会不会造成显示差异”；本部分回答“模型看到 LUT 输入后，自己会输出什么”。

## 11. 问题与定义

把 LUT 看成确定性输入变换 `G`。模型是：

\[
M(x)=r(x)\cdot x
\]

其中 `r(x)` 是模型预测的逐像素标量增益。

比较两条路径：

```text
A       : x    → M
B_model : G(x) → M
```

### 11.1 两个指标

**增益稳定性：**

\[
k_A(p)=\frac{\sum_c M_c(x(p))}{\sum_c x_c(p)},\qquad
k_B(p)=\frac{\sum_c M_c(G(x(p)))}{\sum_c G_c(x(p))}
\]

- `k_A`：模型对原始输入的等效增益；
- `k_B`：模型对 LUT 输入的等效增益；
- `Δk = k_B - k_A`，`δk = |Δk| / max(k_A, ε)`。

`k_B` 不需要等于 `k_A`。模型可以对新输入给出新增益；关键是变化多大、是否稳定。

**近似交换性：**

\[
E_{\text{comm}}(p)=\frac{1}{3}\sum_c
\left|M_c(G(x(p)))-G_c(M(x(p)))\right|
\]

如果 `E_comm` 小，说明“先 LUT 再模型”和“先模型再 LUT”在码值域接近；如果大，说明模型输出随输入域变化。

### 11.2 为什么严格等变一般不成立

假设模型和 LUT 完全可交换：

\[
M(G(x))=G(M(x))
\]

代入 `M(x)=r(x)x`，逐通道写开：

\[
r(G(x))\,G_c(x_c)=G_c(r(x)x_c)
\]

两边除以 `G_c(x_c)`：

\[
r(G(x))=\frac{G_c(r(x)x_c)}{G_c(x_c)}
\]

右边对 R/G/B 三个通道一般不同。左边只有一个标量 `r(G(x))`，不可能同时等于三个不同的通道比值。

要对所有像素精确相等，需要特殊结构，例如：

- 三个通道都是同指数的纯 gamma，并且增益满足 `r(G(x))=r(x)^γ`；
- 或者 `r(x)=1`（模型不改变亮度）。

一般的逐通道 LUT 不满足这些条件，所以严格等变一般不成立。实验测的是它离等变有多远。

### 11.3 “合理”的三个层次

| 层次 | 判断标准 | 本部分是否回答 |
|---|---|---|
| 数值合理 | 无 NaN/Inf、范围 `[0,1]`、没有大面积饱和 | 是 |
| 增益稳定 | `k_B` 与 `k_A` 接近、相关、没有崩 | 是 |
| 任务正确 | `M(G(x))` 与目标 HDR/参考一致 | 否，需要带参考的评测 |

本部分只回答前两层。`k_B≈k_A` 是“模型对输入变换不敏感”的证据，不是“增益在任务意义上正确”的证明。

## 12. 实验设置

| 项目 | 值 |
|---|---|
| 模型 | `HDRnetBT709PaperLumaOnly` |
| 权重 | `net_g_480000.pth`，`params_ema` |
| LUT | `verify_gamma_lut_order.py` 的三条 1D LUT，`s=0.9` |
| 数据 | 26 帧模型输入 PNG |
| 抽查帧 | `frame_000008`, `frame_001345`, `frame_000014`, `frame_000089`, `frame_000253` |
| 分辨率 | 512×512，面积插值 |
| 推理 | eval 模式、不计算梯度，输出 clamp 到 `[0,1]` |

模型结构：

\[
Y=0.2126R+0.7152G+0.0722B
\]

\[
Y'=scale(x)\cdot Y+offset(x)
\]

\[
M(x)=x\cdot\frac{Y'}{Y}
\]

`scale/offset` 由低分辨率 grid 预测，slice 的 guide 是 `Y`。LUT 改变 RGB 和 `Y` 后，`scale/offset` 会变，等效增益 `k` 也跟着变。

选帧不是随机抽样，而是按亮度和 `k` 分布挑选的压力测试集合：`frame_000008`（较平稳）、`frame_001345`（固定 `k` 实验中最差）、`frame_000014`（暗场高增益，平均 `Y=0.114`）、`frame_000089`（较亮，平均 `Y=0.515`）、`frame_000253`（平均 `k` 最低，0.720）。

## 13. 实验过程

对每一帧：

1. 读取 RGB，缩放到 512×512，归一化到 `[0,1]`；
2. 计算原始模型输出 `M(x)`；
3. 计算 LUT 输入 `G(x)`，再算 `M(G(x))`；
4. 逐像素计算 `k_A`、`k_B`、`Δk`、`δk`、`E_comm`、`f_clip`；
5. 对 5 帧汇总，比较不同内容下的变化。

统计口径：

- `k_A`、`k_B` 是 RGB 和比值代理；
- `Δk`、`δk` 按像素统计；
- `E_comm` 按通道、像素统计；
- `f_clip = mean(M(G(x)) >= 1)`；
- 所有统计在 512×512 上进行，不做 4× 降采样。

- `k_A` p5/p95 = 0.716/1.413，`k_B` p5/p95 = 0.710/1.291；
- 回归斜率 0.810，截距 0.138。

也就是说，模型把高增益压低、低增益抬高，增益分布变窄。这不是随机噪声：5 帧的回归斜率都小于 1（0.810–0.959），在这 5 帧上说明 LUT 输入系统性地压缩了增益动态范围，只是在暗场高增益帧上最明显。

可能原因包括 LUT 改变局部对比度/色度分布、暗场 grid 对细节不敏感、训练分布不完全匹配；这些是解释性假设，未做因果验证。

### 15.3 绝对码值误差会低估暗场的相对增益变化

5 帧 `E_comm` 均值 0.0033–0.0106（约 1–2.7/255），p95 0.0089–0.0285。

但 `frame_000014` 的 `E_comm` 均值只有 0.00331，是 5 帧里最小的；它的 `abs(Δk)` 均值却是 0.0511，是 5 帧里最大的。原因是：

- `E_comm` 是码值域绝对差；
- 暗场码值小，5% 的增益差乘上很小的码值，绝对差仍然不大。

所以只看 `E_comm` 会低估暗场的相对增益变化。必须同时看 `abs(Δk)`、相对 `abs(Δk)` 和 `E_comm`。

### 15.4 饱和不是主要原因

5 帧 `f_clip` 都 ≤0.12%，`frame_000008` 最高也只有 0.112%。  
所以 `k_B` 的变化不是输出 clamp 造成的，而是模型对输入内容/分布的真实响应。

## 16. 26 帧 `B_model` 实验方案

### 16.1 路径与指标

```text
A       : x    → M
B_model : G(x) → M
```

逐帧统计：

- `k_A`、`k_B` 的 mean/median/p5/p95；
- `Δk`、`δk` 的 mean/median/p95/max；
- `abs(Δk)>0.02/0.05/0.10` 的像素比例；
- `corr(k_A,k_B)`；
- `E_comm` mean/p95/max；
- `f_clip`；
- `Y(G(x))/Y(x)` 和 `Y(M(G(x)))/Y(M(x))`。

### 16.2 建议判定标准

以下是工程建议，不是行业标准：

| 指标 | 建议通过条件 |
|---|---|
| `median abs(Δk)` | `< 0.02` |
| `p95 abs(Δk)` | `< 0.05` |
| `abs(Δk)>0.10` 像素比例 | `< 1%` |
| `corr(k_A,k_B)` | `> 0.95` |
| `E_comm` 均值 | `< 1/255 ≈ 0.0039` |
| `f_clip` | `< 1%` |

判定：

- **≥24/26 帧通过**：模型侧影响小，“LUT 只是输入变化”在本模型/本数据上成立；
- **多数帧通过，少数暗场/高增益帧不通过**：模型影响是内容相关的，需要按内容分析；
- **多数帧不通过**：输入域偏移显著，LUT 前置不能只靠模型泛化，需要重训/微调或改回 LUT 后置。

> 5 帧抽查里已经有 `frame_000014` 不满足 `p95 abs(Δk)<0.05`、`abs(Δk)>0.10<1%`，所以不能提前下“所有帧都稳定”的结论。

## 17. 第二部分结论

1. **LUT 对模型是输入变换，不是模型结构变化。** 模型只执行 `M(G(x))`，`k` 变化来自 `r(G(x))`。
2. **严格等变一般不成立。** 逐通道 LUT 下，完全可交换要求 `r(G(x))` 同时等于三个通道的比值，一个标量做不到。
3. **多数帧近似稳定。** 4/5 帧平均相对 `abs(Δk)` 1.39%–2.89%，`corr` 0.921–0.984，`abs(Δk)>0.05` 像素 1.73%–3.83%。
4. **暗场高增益帧明显偏离。** `frame_000014` 平均 `abs(Δk)=0.0511`，44.08% 像素 `>0.05`，14.51% 像素 `>0.10`，回归斜率 0.810。
5. **绝对码值误差会低估暗场相对增益变化。** `frame_000014` 的 `E_comm` 最小，但 `abs(Δk)` 最大；必须同时看绝对和相对指标。
6. **饱和不是主要原因。** 5 帧 `f_clip` 都 ≤0.12%。
7. **最终判断需要 26 帧 `B_model`。** 5 帧已经出现一个例外，不能提前下“所有帧都稳定”的结论。

一句话：

> **LUT 对模型只是输入变换；模型在多数帧上能给出接近原增益的结果，但这种稳定性是内容相关的，暗场高增益帧会明显偏离。**
