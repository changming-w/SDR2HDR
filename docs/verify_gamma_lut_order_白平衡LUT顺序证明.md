## 摘要

本文档证明：在“面板三通道原生 gamma、满幅亮度、S 曲线均不一致，显示端 3×1D LUT 同时承担 gamma 校正和白平衡”的前提下，**白平衡/校正 LUT 必须放在 luma-only 模型之后**，即信号流应为：

```text
SDR → 模型（逐像素标量增益 k）→ 白平衡/校正 LUT → 面板
```

如果反过来，把 LUT 放在模型之前：

```text
SDR → 白平衡/校正 LUT → 模型（逐像素标量增益 k）→ 面板
```

模型的统一亮度增益会被面板的逐通道 gamma 翻译成逐通道增益 `k^γ_c`。由于三通道 `γ_c` 不同，R/G/B 三个通道的线性光增益不同，白点偏移、产生色偏；在高光区，三通道 LUT 码值不同还会导致不同的 clipping 顺序，进一步偏色。

脚本用两类实验量化这一结论：

| 实验 | 数据 | 关键结果 |
|---|---|---|
| 灰阶合成测试 | 7 个灰阶 × 4 个增益 | Path A 白点误差最大 0.00151（低于 0.004 可见阈值）；Path B 最大 0.01303；`ΔE(A,B)` 最大 6.510 |
| 真实图像测试 | 26 张 4K 帧 | Path B 相对 Path A 的 ΔE 均值 0.378–2.560；最差帧 69.00% 像素 ΔE>2；灰色像素 Path B 白点误差均值 0.00333–0.01252 |

最终结论：**顺序错的不是“亮度”本身，而是“颜色”**。很多情况下 Path B 的亮度增益看起来接近 `k^2.2`，但白点和色度已经明显改变。

## 1. 问题定义

### 1.1 术语对齐

脚本里的“白平衡模块”不是相机端的场景白平衡，而是**显示端的 3×1D 校正 LUT**。它同时做两件事：

1. 反演面板三通道各自不同的原生 gamma；
2. 把面板因三通道满幅不同而偏离 D65 的白点拉回 D65。

因此它本质上是一个**逐通道非线性映射**：

```text
C_c(V),  c ∈ {R, G, B}
```

luma-only 模型则是一个**逐像素标量增益**：

```text
out = k · RGB
```

其中 `k` 对同一像素的三个通道相同。脚本要证明的是：逐通道非线性的 `C_c` 和逐像素标量的 `k`，谁先谁后，结果不一样。

### 1.2 两条路径

| 名称 | 信号流 | 白平衡模块位置 | 脚本评价 |
|---|---|---|---|
| Path A | `V → ×k → C_c(·) → 面板` | 模型后 | 正确顺序 |
| Path B | `V → C_c(·) → ×k → 面板` | 模型前 | “当前做法”/错误顺序 |

### 1.3 待证明命题

**命题**：在面板三通道响应不一致时，Path B 不能保持 Path A 的白点和色度；Path B 的逐通道线性光增益为 `k^γ_c`，而 Path A 为统一的 `k^2.2`。

本文档从三个层面给出证据：

1. **数学推导**：在纯幂律面板模型下给出闭式证明；
2. **数值实验**：在带 S 曲线、10bit LUT 量化、clipping 的真实脚本模型中验证；
3. **真实图像**：用 26 张 4K 帧的真实模型增益 `k` 统计 ΔE 和白点误差。

## 2. 方案设计

### 2.1 受控 A/B 实验

脚本不重新训练模型，也不假设模型内部结构。它读取真实模型的输入 `i` 和输出 `o`，逐像素估计：

```python
si = i.sum(-1)
k = o.sum(-1) / si
```

对于 luma-only 模型，未 clipping 时：

```text
o ≈ k · i
```

所以 `sum(o)/sum(i)` 就是模型增益 `k`。然后让**同一个 `k`** 分别走两条信号链：

```text
Path A:  V ──×k──> C_c(·) ──> 面板 P_c ──> 线性光
Path B:  V ──C_c(·)──> ×k ──> 面板 P_c ──> 线性光
```

这样只改变“顺序”一个变量，其他条件完全相同，能够干净地隔离顺序效应。

> 注意：真实把 LUT 移到模型前面后，模型输入分布会从 SDR 码值变成 panel code，`k` 本身也会变化。脚本固定同一个 `k`，证明的是“顺序”这一项的影响，不是完整的端到端重跑。这一点在“局限性”中会再次说明。

### 2.2 增益 `k` 的估计

`image_test` 中：

```python
si = i.sum(-1)
k = np.where(si > 1e-3, o.sum(-1) / np.maximum(si, 1e-6), 1.0)[..., None]
```

- 对 RGB 三通道求和，而不是只取 Y；对 luma-only 模型，任意正权重求和都能得到同一个 `k`；
- `si > 1e-3` 避免极暗像素除零/噪声放大；
- 极暗像素回退 `k=1`；
- 输出是 8bit PNG，`k` 包含量化、舍入和 clipping；因此它是真实模型增益的一个合理代理，不是模型内部浮点增益的精确值。

### 2.3 两个测试

**灰阶测试 `gray_test`**

- 灰阶 `V ∈ {0.05, 0.1, 0.2, 0.3, 0.5, 0.7, 0.9}`
- 增益 `k ∈ {0.6, 0.8, 1.0, 1.2}`
- 对每个 `(V, k)` 计算 Path A/B 的最终线性光，再转 XYZ、u'v'、Lab。

**真实图像测试 `image_test`**

- 26 张 4K PNG；
- 输入/输出都做 4× 降采样（`i[::4, ::4]`）加速；
- 用输入/输出估计逐像素 `k`；
- 同一个 `k` 分别走 Path A/B；
- 统计逐像素 ΔE76、灰色像素白点误差，并保存 ΔE 热力图。

### 2.4 评价指标

| 指标 | 定义 | 用途 |
|---|---|---|
| `Δu'v'` | CIE 1976 u'v' 空间中的欧氏距离 | 衡量白点/色度偏移；0.004 是常用可见阈值 |
| `ΔE76` | Lab 空间欧氏距离 | 衡量整体颜色差异；ΔE>2 是常用“明显可见”粗略阈值 |
| 亮度增益 | 输出 Y / 参考 Y | 衡量亮度变化，不含色度信息 |
| `k` 分布 | 逐像素模型增益 | 解释误差来源和画面差异 |

使用两个色彩指标的原因：

- `Δu'v'` 只反映色度/白点，不包含明度；
- `ΔE76` 同时包含明度和色度；
- 两者结合才能区分“暗部白点偏了但 ΔE 不大”和“亮部明显变色”。

## 3. 面板模型与 LUT 构造

### 3.1 面板假设

```python
NATIVE_GAMMA = {'R': 2.45, 'G': 2.25, 'B': 2.05}
S_CURVE      = {'R': 0.10, 'G': 0.05, 'B': 0.15}
AMP          = [0.90, 1.00, 1.10]
TARGET_GAMMA = 2.2
LUT_SIZE     = 1024
LUT_OUT_BITS = 10
```

| 参数 | 含义 |
|---|---|
| `NATIVE_GAMMA` | 三通道原生 gamma，故意各不相同，且都不是 2.2 |
| `S_CURVE` | 在幂律上叠加的 S 形扭曲，使面板响应不是纯幂律 |
| `AMP` | 三通道满幅线性亮度；R 最弱、B 最强，所以原生白点偏蓝 |
| `TARGET_GAMMA` | 校正目标：gamma 2.2 |
| `LUT_SIZE` | LUT 输入 1024 点（10bit） |
| `LUT_OUT_BITS` | LUT 输出 10bit 量化 |

面板原生响应：

```python
def panel_native(v, ch):
    v = np.clip(v, 0.0, 1.0)
    base = np.power(v, NATIVE_GAMMA[ch])
    s = S_CURVE[ch]
    return np.clip(base + s * np.sin(np.pi * v) * base * (1 - v) * 2, 0.0, 1.0)
```

即：

```text
P_c(v) = clip( v^γ_c + s_c · sin(πv) · v^γ_c · (1-v) · 2, 0, 1 )
```

面板实际发出的线性光：

```text
L_c = a_c · P_c(code_c)
```

其中 `a_c = AMP[c]`。

脚本的 `panel_emit` 会再除以 `s`，把校正白 `V=1` 归一化到 1；本节的物理推导用未归一化的 `L_c`，两条路径的比值不受这个公共因子影响。

> 为什么要故意让三通道不一样？因为如果三通道响应完全一致且是纯 2.2 幂律，LUT 三通道相同，顺序不会产生色偏。脚本构造的是最坏情况，把“逐通道差异”这个变量放大。

### 3.2 校正 LUT 的构造

目标是让输入码值 `V` 经过 LUT 后，面板发出统一的目标线性光：

```text
a_c · P_c(C_c(V)) = s · V^2.2
```

所以：

```text
C_c(V) = P_c^{-1}( s · V^2.2 / a_c )
```

其中：

```text
s = min(AMP) = 0.9
```

为什么取 `s=0.9`？

- R 通道满幅只有 0.9；如果目标白点设为 1.0，R 永远达不到；
- 取 0.9 让三通道都能达到；
- 代价是 G/B 分别留了约 10% 和 18% 的余量。

代码实现：

```python
s = AMP.min()
dense = np.linspace(0, 1, 65536)
vin = np.linspace(0, 1, LUT_SIZE)

for i, ch in enumerate('RGB'):
    resp = panel_native(dense, ch)
    resp = np.maximum.accumulate(resp)        # 保证单调，便于求逆
    target = s * np.power(vin, TARGET_GAMMA) / AMP[i]
    code = np.interp(target, resp, dense)    # 数值求逆
    q = 2 ** LUT_OUT_BITS - 1
    luts.append(np.round(code * q) / q)      # 10bit 量化
```

脚本打印的三个例子：

```text
灰 0.2 经 LUT -> RGB 码值 [0.2264 0.1941 0.1531]
灰 0.5 经 LUT -> RGB 码值 [0.5166 0.4736 0.3993]
灰 0.8 经 LUT -> RGB 码值 [0.8117 0.7619 0.688 ]
```

可以看到：

```text
C_R > C_G > C_B
```

R 最弱，所以驱动码值最高；B 最强，所以驱动码值最低。这正是白平衡在起作用，也是后面 clipping 顺序问题的根源。

### 3.3 无模型校验

无模型时，校正后的灰阶应该严格是 D65。脚本先做校验：

```text
无模型时校正后灰阶 Δu'v' (应≈0): 0.00107
```

0.00107 是 10bit LUT 量化和数值反演的噪声底，已经低于人眼可见阈值（约 0.004）。

## 4. 理论证明

### 4.1 符号与引理

**定义**：

- `V`：目标显示码值，目标 gamma 为 2.2；
- `k`：luma-only 模型的逐像素标量增益；
- `P_c(·)`：面板通道 `c` 的原生响应；
- `a_c`：面板通道 `c` 的满幅线性亮度；
- `C_c(·)`：显示端 3×1D 校正 LUT；
- `s = min(a_c) = 0.9`：公共目标白电平。

**引理 1（LUT 反演性质）**：

在忽略量化误差时，`C_c` 满足：

```text
a_c · P_c(C_c(V)) = s · V^2.2
```

即校正后，三个通道在目标码值 `V` 处发出相同的线性光 `s·V^2.2`，白点为 D65。

### 4.2 定理 1：顺序对线性光增益的影响

**假设**：面板为纯幂律，忽略 S 曲线和 clipping：

```text
P_c(x) = x^γ_c
```

**定理 1**：

```text
L_c^A = s · V^2.2 · k^2.2
L_c^B = s · V^2.2 · k^γ_c
```

**证明**：

Path A（模型在 LUT 前）：

```text
L_c^A = a_c · P_c(C_c(kV))
       = a_c · C_c(kV)^γ_c
       = s · (kV)^2.2
       = s · V^2.2 · k^2.2
```

Path B（模型在 LUT 后）：

```text
L_c^B = a_c · P_c(k · C_c(V))
       = a_c · k^γ_c · C_c(V)^γ_c
       = k^γ_c · [ a_c · C_c(V)^γ_c ]
       = s · V^2.2 · k^γ_c
```

证毕。

两条路径的逐通道比值：

```text
L_c^B / L_c^A = k^(γ_c - 2.2)
```

### 4.3 推论：色偏条件

**推论 1（纯幂律假设下）**：

1. 如果 `γ_R = γ_G = γ_B = 2.2`，则 `L_c^B / L_c^A = 1`，两种顺序完全等价；
2. 如果三通道 gamma 相同但不等于 2.2，则所有通道的比值相同，**颜色不变，但亮度增益从 `k^2.2` 变成 `k^γ`**；
3. 如果三通道 gamma 不同（脚本的情况），则逐通道比值不同，**白点偏移、产生色偏**。

脚本的参数：

```text
γ_R = 2.45  →  γ_R - 2.2 = +0.25
γ_G = 2.25  →  γ_G - 2.2 = +0.05
γ_B = 2.05  →  γ_B - 2.2 = -0.15
```

Path B 的逐通道线性增益 `k^γ_c` 与 Path A 的统一增益 `k^2.2` 对比：

| 通道 | γ_c | γ_c−2.2 | k=0.6 | k=0.8 | k=1.2 |
|---|---:|---:|---:|---:|---:|
| R | 2.45 | +0.25 | 0.2861 | 0.5789 | 1.5631 |
| G | 2.25 | +0.05 | 0.3168 | 0.6053 | 1.5072 |
| B | 2.05 | −0.15 | 0.3509 | 0.6329 | 1.4532 |
| 理想 A | 2.20 | 0 | 0.3250 | 0.6121 | 1.4935 |

关键比值：

```text
k = 0.8：R/B = 0.5789 / 0.6329 = 0.915
k = 1.2：R/B = 1.5631 / 1.4532 = 1.076
k = 0.6：R/B = 0.2861 / 0.3509 = 0.815
```

解释：

- `k < 1`（压暗）：R 被压得比 B 多，红色相对减少，画面偏蓝；
- `k > 1`（提亮）且未 clipping：R 被抬得比 B 多，画面偏暖；
- `k` 离 1 越远，色偏越大；`k=0.6` 时 R/B 只有 0.815，已经非常明显。

### 4.4 定理 2：clipping 阈值不同

**定理 2**：

- Path A 的 clipping 条件为 `k·V = 1`，阈值 `k_A = 1/V`，三通道相同；
- Path B 的 clipping 条件为 `k·C_c(V) = 1`，阈值 `k_c = 1/C_c(V)`，三通道不同。

**证明**：直接由两条路径中 `k` 的作用位置得到。

**推论 2**：因为 `C_R > C_G > C_B`，所以：

```text
k_R < k_G < k_B
```

R 最先 clip，B 最后 clip。

以 `V=0.9` 为例：

```text
C(0.9) = [0.9078, 0.8589, 0.7954]
1/C    = [1.102,  1.164,  1.257]
```

当 `k=1.2` 时：

- Path A：`k > 1/V = 1.111`，三通道全部 clip，输出中性白；
- Path B：R 和 G 已经 clip，B 还没 clip，B 通道相对更亮，高光反而偏冷/偏蓝。

实测这一点的 `ΔE(A,B)=5.273`，非常大。所以 Path B 不仅有“gamma 指数不对”的误差，还有“clipping 顺序不同”的第二个独立误差源。

### 4.5 S 曲线与实际面板

真实面板响应 `P_c` 含 S 曲线，不是纯幂律，因此有效指数随 `V` 变化：

```text
d log P_c / d log v  ≠ 常数
```

所以上面的 `k^γ_c` 是一阶解释；脚本的数值实验使用完整的 `P_c`，包含：

- S 曲线；
- 10bit LUT 量化；
- `np.maximum.accumulate` 单调化；
- Path A/B 不同位置的 `np.clip`；
- 三通道满幅不同导致的 headroom 差异。

因此，**数学定理解释机制，数值实验给出实际量级**；两者结合构成完整证明。

### 5.1 函数总览

| `apply_lut` | 66–69 | 3×1D LUT 线性插值 |
| `panel_emit` | 72–75 | 校正后码值 → 三通道线性亮度 |
| `to_xyz` | 78–79 | BT.709 线性 RGB → XYZ |
| `xyz_to_uv` | 82–85 | XYZ → CIE 1976 u'v' |
| `xyz_to_lab` | 88–93 | XYZ → Lab，参考白 D65 |
| `path_a` | 96–97 | 模型在前、LUT 在后 |
| `path_b` | 100–101 | LUT 在前、模型在后 |
| `gray_test` | 104–123 | 灰阶 A/B 对比 |
| `image_test` | 126–146 | 真实图像 A/B 对比 |
| `main` | 149–164 | 参数解析与流程 |

### 5.2 两条路径

```python
def path_a(v, k, luts, s):
    return panel_emit(apply_lut(np.clip(v * k, 0, 1), luts), s)

def path_b(v, k, luts, s):
    return panel_emit(np.clip(apply_lut(v, luts) * k, 0, 1), s)
```

唯一的区别就是 `k` 乘在 `apply_lut` 之前还是之后。

### 5.3 色彩学工具

- `to_xyz`：用 BT.709 矩阵把线性 RGB 转到 XYZ；
- `WHITE_XYZ = M709 @ ones`：D65 白点；
- `xyz_to_uv`：计算 CIE 1976 u'v'：  
  `u' = 4X/(X+15Y+3Z)`，`v' = 9Y/(X+15Y+3Z)`；
- `xyz_to_lab`：以 D65 为参考白转 Lab；
- `ΔE76`：Lab 空间的欧氏距离，综合了明度和色度；
- `Δu'v'`：只反映色度/白点偏移，不包含明度。

### 5.4 `gray_test`

核心逻辑：

```python
y_in = to_xyz(path_a(np.full(3, g), 1.0, luts, s))[1]

for k in ks:
    la = path_a(np.full(3, g), k, luts, s)
    lb = path_b(np.full(3, g), k, luts, s)
    xa, xb = to_xyz(la), to_xyz(lb)

    dua = np.linalg.norm(xyz_to_uv(xa) - uv_d65)
    dub = np.linalg.norm(xyz_to_uv(xb) - uv_d65)
    de  = np.linalg.norm(xyz_to_lab(xa) - xyz_to_lab(xb))
```

打印的各列含义：

| 列 | 含义 |
|---|---|
| `A Δuv` | Path A 输出白点相对 D65 的偏移 |
| `B Δuv` | Path B 输出白点相对 D65 的偏移 |
| `ΔE(A,B)` | Path A 与 Path B 的整体颜色差 |
| `增益A` | Path A 的 Y 亮度增益，相对无模型 Path A |
| `增益B` | Path B 的 Y 亮度增益，相对无模型 Path A |
| `k^2.2` | 理想 Path A 亮度增益（含 `kV` clipping） |

`y_in` 取的是同一灰阶、`k=1` 时 Path A 的 Y，作为亮度参考。

### 5.5 `image_test`

核心逻辑：

```python
i = cv2.imread(...)[..., ::-1].astype(np.float32) / 255
o = cv2.imread(...)[..., ::-1].astype(np.float32) / 255
i, o = i[::4, ::4], o[::4, ::4]          # 4× 降采样加速

si = i.sum(-1)
k = np.where(si > 1e-3, o.sum(-1) / np.maximum(si, 1e-6), 1.0)[..., None]

la = path_a(i, k, luts, s)
lb = path_b(i, k, luts, s)

de = np.linalg.norm(
    xyz_to_lab(to_xyz(la)) - xyz_to_lab(to_xyz(lb)), axis=-1
)

gray = np.ptp(i, axis=-1) < 2 / 255
uv_d65 = xyz_to_uv(WHITE_XYZ)
duv_b = np.linalg.norm(
    xyz_to_uv(to_xyz(lb)) - uv_d65, axis=-1
)[gray & (si > 0.15)]
```

几个设计点：

1. **同一 `k` 走两条路径**：只改变顺序，不改变模型增益，干净地隔离顺序效应。
2. **`k` 从真实输入/输出估计**：保留模型逐像素、逐内容的增益分布。
3. **灰色像素掩码**：`ptp(i) < 2/255` 表示输入 RGB 三通道几乎相等；对这些像素，输出偏离 D65 就是白点误差，不是内容本身的颜色。
4. **`si > 0.15`**：排除太暗的像素，避免 u'v' 数值不稳定。
5. **热力图**：`de / 5 * 255`，把 ΔE 0–5 映射到 0–255；超过 5 的会饱和，所以热力图只用于看空间分布，精确统计看打印值。

## 8. 结论与工程建议

### 8.1 正确顺序

```text
SDR → 模型（×k）→ 白平衡/校正 LUT → 面板
```

白平衡模块放在模型**后面**。理由：

1. 模型是 luma-only，输出是 `k·RGB`，它在显示无关的码值域里只改变亮度，色度天然不变；
2. 校正 LUT 是面板响应的逆，必须作为**最后一步**把目标码值翻译成具体面板的驱动码；
3. 这样最终线性光为 `s·V^2.2·k^2.2`，三通道一致，白点保持 D65。

### 8.2 如果当前是 Path B，怎么修？

优先级从高到低：

1. **把 LUT 移到模型后面**（推荐）。这是最干净、最符合物理意义的做法。
2. 如果 LUT 必须在前，按通道补偿增益：

   ```text
   k_c = k^(2.2 / γ_c)
   ```

   但这只在纯幂律、无 clipping 时近似成立；有 S 曲线和 clipping 时，需要数值求解：

   ```text
   P_c(k_c · C_c(V)) = P_c(C_c(kV))
   ```

   解随 `V` 变化，不推荐。
3. 在 panel code 解码到线性光后做增益，再重新编码。等价于把增益放到正确的线性域。
4. 如果模型训练时输入就是 LUT 后的 panel code，那属于另一套 pipeline，需要重新训练/标定；不能只交换顺序。

### 8.3 验收标准

建议：

- 灰阶白点误差 `Δu'v' < 0.004`；
- 大部分像素 `ΔE < 2`；
- 高光区没有明显的冷暖翻转；
- 灰色像素白点误差在全亮度范围内稳定。

当前 Path B：

- 灰阶最大 `Δu'v'=0.01303`，最大 `ΔE=6.510`；
- 26 帧中 22 帧灰色白点误差 >0.004；
- 最差帧 69.00% 像素 `ΔE>2`。

已经明显不满足。

## 9. 局限性与适用范围

1. **面板参数是合成假设**，不是实测的某台显示器。脚本证明的是机制和量级，不是特定设备的精确误差。真实面板需要实测 `P_c` 和 `a_c` 后重新跑。
2. **A/B 使用同一个 `k`**。真实把 LUT 移到模型前面后，模型输入分布会从 SDR 码值变成 panel code，`k` 本身也会变，误差可能更大或不同。脚本隔离的是“顺序”这一个变量，不是完整的端到端重跑。
3. **`k` 从 8bit 图像估计**，包含量化、clipping 和舍入；极暗像素用 `k=1` 兜底。
4. **4× 降采样**加速，统计上可接受，但不是逐像素全分辨率。
5. **0.004 和 ΔE>2 是经验阈值**，不是严格标准；不同观察条件、不同面板会有所不同。
6. **Path A/B 的 clipping 行为不同**：Path A 在 LUT 前 clip，Path B 在 LUT 后逐通道 clip。高光区的亮度增益对比会受 headroom 影响；颜色结论是稳健的，但亮度数字要结合 clipping 解释。
7. **S 曲线让有效指数随 `V` 变化**，所以纯幂律推导只是一阶解释；真正的证据是脚本的数值结果。
8. **真实显示管线可能还有 3D LUT、矩阵、局部调光、tone mapping 等**；脚本只建模了 3×1D LUT + 逐通道 EOTF。
9. **脚本不评价模型本身的画质**。它比较的是“同一模型增益下，两种顺序造成的显示差异”，不是模型输出与 HDR 参考的差距。
